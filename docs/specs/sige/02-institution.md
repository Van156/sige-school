## 1. Objective and scope

The institution tenant and its academic structure: the root-only institution lifecycle (create with its rector, edit, delete, switch into), the institution data page, and the structure an admin builds in order (F3): campuses, academic levels, courses, subjects, periods, evaluation criteria.

- Photos beyond the institution logo (OD-12).

## 2. Data

Tables follow foundation §5.2 and conventions R2.1–R2.6 (UUID text ids, `organization_id` first in every index, composite tenant-safe FKs, `timestamptz`, Spanish-valued enums). This module owns:

| Table                 | Notes specific to this spec                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `institution_profile` | `organization_id` PK/FK (cascade). `nit` text null (≤ 20) with a partial unique index `unique(nit) where nit is not null`; `address` ≤ 200, `phone` ≤ 20, `email` ≤ 100, `municipality` ≤ 100, `department` ≤ 100, `resolution` ≤ 100, `current_academic_year` text not null (4 digits), `timezone` text not null default `America/Bogota`. Name, slug and logo live on `organization`.                                                                                                                            |
| `campus`              | `name` ≤ 150, `code` ≤ 20, `address` ≤ 200, `jornada` enum (`manana`, `tarde`, `completa`; default `completa`), `is_main`, `active` (default true). Partial uniques `unique(organization_id, code) where code is not null` and `unique(organization_id) where is_main`. Index `(organization_id, name)`.                                                                                                                                                                                                           |
| `grade_level`         | `campus_id`, `name` ≤ 50, `order_num int not null default 0 check (order_num >= 0)`. `unique(campus_id, name)`; index `(organization_id, campus_id, order_num)`.                                                                                                                                                                                                                                                                                                                                                   |
| `course`              | `campus_id`, `level_id` null, `director_person_id` null, `name` ≤ 50, `academic_year`, `shift` enum (`Mañana`, `Tarde`, `Nocturna`, `Única`, `Sabatina`), `max_students int check (1..60) default 40`. `unique(campus_id, name, academic_year, shift)`; composite FK `(organization_id, campus_id, level_id) → grade_level(organization_id, campus_id, id)` so the level shares the campus (needs `unique(organization_id, campus_id, id)` on `grade_level`). Index `(organization_id, academic_year, campus_id)`. |
| `subject`             | `name` ≤ 100, `code` ≤ 20; partial `unique(organization_id, code) where code is not null`.                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `academic_period`     | `academic_year`, `order_num int check (1..4)`, `name` ≤ 50, `short_name` ≤ 10, `start_date`, `end_date`, `is_active`. `unique(organization_id, academic_year, short_name)`, `check (start_date < end_date)`, partial `unique(organization_id) where is_active`. Date overlap inside a year is a service check (INS-R9).                                                                                                                                                                                            |
| `grade_criterion`     | `name` ≤ 100, `weight numeric(5,2) check (weight > 0 and weight <= 100)`, `description` ≤ 300, `order_num int check (>= 1)`. Σ weights = 100 is validated, not enforced (foundation §5.5).                                                                                                                                                                                                                                                                                                                         |

`current_academic_year` has no default constraint beyond "four digits"; the migration default is the migration-time year and the provisioning service always sets it explicitly.

Migration notes: one migration creates the enums and the six tables; `grade_level` gets the extra unique before `course` references it. Deleting an institution cascades from `organization` (R2.6) but is refused by the service first (INS-R4). Tenant-safe FKs mean no `course`/`grade_level`/`campus` row can reference another tenant's parent.

### 2.1 Seed on institution creation

`seedInstitutionDefaults(orgId)` (called inside `institution.create`, §3.1) inserts the institution's default rows owned by later modules. Today it creates the seven default achievements of foundation §5.5 (module 11 owns the list; the function is a no-op until that table exists). It does **not** create criteria or periods (OQ-INS-2).

### 2.2 File storage

`FileStoragePort` (foundation R3.23, OD-12), in `packages/api/src/storage/port.ts`:

```ts
interface FileStoragePort {
  put(key: string, bytes: Uint8Array, contentType: string): Promise<{ url: string }>;
  delete(key: string): Promise<void>;
}
```

Adapters: local disk (dev/test, served by a static Hono route) and S3-compatible (production, env-selected like `EmailSender`). Logo keys are `logos/{organizationId}/{contentHash}.{ext}`; `organization.logo` stores the returned URL. Replacing a logo deletes the previous object after the new one is stored.

## 3. API

Router files: `routers/sige/institution.ts` exports `institutionAdminRouter` (platform), `institutionRouter` (profile), `campusRouter`, `levelRouter`, `courseRouter`, `subjectRouter`, `periodRouter`, `criterionRouter`. Org procedures are `sigeProcedure.use(requirePermission(...))`; platform procedures are `platformProcedure(...)` (existing builder) and take an explicit `institutionId` because they have no tenant context (R3.2 applies to tenant routers only). Errors per foundation R3.5; delete conflicts return `HAS_DEPENDENTS` (409) with the message of §4.2 in `message` and no leak of other tenants' rows.

Shared zod fragments (`packages/api/src/sige/schemas/institution.ts`, also imported by the web forms): `institutionFieldsInput`, `campusInput`, `levelInput`, `courseInput`, `subjectInput`, `periodInput`, `criterionInput`. All strings are trimmed; empty optional strings become `null`.

#### 3.1.1 `institutionAdmin.create` algorithm

1. Validate input (§4.1). Check `nit` and the rector's document and email uniqueness before any write.
2. `provisionUser` (module 03, R1.18) for the rector with role `owner`, `must_change_password = true`, initial password = document number; before creating the organization set `user.maxOrganizations = 1` on the rector (R1.12, verify the superadmin override against 1.7.5).
3. Create the organization with the better-auth server API using the rector as creator (so the owner member row is created by the organization plugin and existing audit hooks fire); slug = slugified name, suffixed `-2`, `-3` on collision.
4. Insert `institution_profile` (with `current_academic_year` from the input), run `seedInstitutionDefaults`.
5. Any failure after step 2 compensates by deleting what was created in reverse order (R1.18); covered by a fault-injection test at each step.

### 3.3 Structure CRUD

Pattern for each entity `X` in `campus`, `level`, `subject`, `period`, `criterion` (bounded lists, R3.9) and `course` (server list, R3.8): `X.list`, `X.get`, `X.create`, `X.update`, `X.delete`, with permission `X:read` for list/get and `X:create|update|delete` for the mutations (foundation §4.2). All filter by `context.org.id`; `get/update/delete` of another tenant's id → `NOT_FOUND`. Mutations return the updated entity; deletes return `{ deleted: true }`. One exception to the read gate: `period.list` accepts `period:read` **or** `grade:read`, so a teacher (who holds no `period:read`) gets the GRD-01 lock pills and the GRD-03 period select; `period.get` and `period.summary` stay on `period:read`.

### 3.4 Cross-module hook

`criterion.create/update/delete` that changes a weight or the criterion set calls `gradeRecalculation.recomputeFinals({ scope: "open" })` (port defined by module 06, OD-8) in the same transaction: finals are recomputed for every unlocked offering × period and never for locked ones. Until module 06 ships the port is a no-op. The response of `criterion.update` includes `affectedFinals: number` (0 before module 06).

### 4.2 Delete rules (R3.4 delete policy; foundation §6.4)

| Entity      | Refused when                                                                             | Message                                                 |
| ----------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------- |

| Campus      | has classrooms or time blocks                                                            | "La sede tiene salones o bloques horarios asociados."   |
| Campus      | has students                                                                             | "La sede tiene estudiantes asociados."                  |
| Level       | has courses                                                                              | "El nivel tiene cursos asociados."                      |
| Course      | has students                                                                             | "El grado tiene estudiantes asociados."                 |
| Course      | has offerings (subject × course)                                                         | "El grado tiene asignaturas asignadas."                 |

| Criterion   | has `grade_record` rows                                                                  | "El criterio tiene notas registradas."                  |
| Institution | has students or grade records (foundation §6.4; prototype refused on any campus or user) | "La institución tiene estudiantes o notas registradas." |

Dependents are detected by the FK `restrict` (R2.6): the service catches the constraint violation, maps it to the message above and never relies on a pre-check alone (race-safe). Deleting the main campus is allowed when it has no dependents; the institution then has no main campus until another is flagged.

### 4.3 Behavioural rules

- INS-R1 **Role gates.** Create/update/delete = `X:create|update|delete` (owner and admin). Coordinators and teachers get read-only list screens: no "Nuevo…" button, no row actions (`canManage = useCan("X:create")`), forms unreachable (route guard → `NoPermission`).
- INS-R2 **One main campus.** Enforced by the partial unique index and the service message of §4.1; a concurrent double-flag returns `CONFLICT` mapped to the same message.
- INS-R3 **Inactive campuses** (`active = false`) are excluded from the campus selects of new courses, classrooms, time blocks and students, and flagged "Inactiva" in lists; existing rows keep their campus. Help text: "Las sedes inactivas no estarán disponibles para selección".
- INS-R4 **Institution delete** follows §4.2 and then the existing org-deletion flow (also removes `institution_profile` and the logo object).
- INS-R5 **Active period.** Exactly one `is_active` per institution (R2.7). The form switch "Periodo Activo" (default on for the first period, off otherwise) calls `period.activate` when turned on; turning it off on the active period is rejected: "Debe haber un periodo activo. Active otro periodo para cambiar." Four periods per year is a warning on the list ("Este año tiene {n} de 4 periodos."), not a limit.
- INS-R6 **Immutable parents.** A level's campus is immutable (the edit form shows it disabled, as in the prototype). A course's campus is immutable once the course has students, offerings or schedule slots: "No se puede cambiar la sede de un grado con estudiantes o asignaturas."
- INS-R7 **Criteria weights.** The list shows a footer "Peso total: {n}%" when Σ = 100 and the warning callout **"Los pesos suman {n}%"** with "Los pesos de los criterios deben sumar 100% para calcular bien las notas finales." otherwise. Changing weights recomputes open finals (§3.4, OD-8). Saving never blocks on Σ ≠ 100.
- INS-R8 **Teacher as director.** `directorPersonId` extends the teacher's visible students to that course (OD-21); removing the director removes that scope unless the teacher also has an active offering there.
- INS-R9 **Period overlap** compares closed date ranges within the same `academic_year`; checked in the service inside the write transaction with a `for update` lock on the institution's periods.
- INS-R10 **Logo** accepts PNG, JPG/JPEG, GIF, WEBP up to 2 MB; others → `BAD_REQUEST` "Formato no permitido. Use PNG, JPG, JPEG, GIF o WEBP." / "El logo supera 2 MB." Content type is verified from the bytes.
- INS-R11 **Institution creation is atomic from the user's view** (§3.1.1); when the logo upload fails after a successful create the UI keeps the institution, toasts "Institución creada, pero no se pudo subir el logo" and opens the edit form.
- INS-R12 **Tenant source.** No tenant procedure takes an institution id; platform procedures take `id`/`institutionId` and require platform permissions. A rector cannot call `institutionAdmin.*`.
