## Objective

Replace the shared `DataTable` in `apps/web` with a reusable, server-driven table adapted from tablecn's Base UI variant (commit `5c2a102`, MIT): column headers with sort, simple and advanced filters, multi-sort, column visibility, selection with action bar, pagination, skeleton, URL state via TanStack Router `validateSearch`; migrate all consumers.

## Constraints

- No `nuqs`. TanStack Table v9 API (`@tanstack/react-table` 9.x).
- `packages/ui` stays app-agnostic; `shared/**` never imports features; route files stay thin.
- Files copied or derived from tablecn carry an MIT attribution header.
- Do not touch the user's uncommitted `packages/infra/.env.schema` edit or untracked `Makefile`.
- Conventional commits, no AI attribution. Formatters run before commit so lefthook hooks are no-ops.
- Deterministic stories; a11y `test = "error"`.

## T1 decision record

- URL shape: TanStack Router's default `stringifySearch`/`parseSearch` JSON-encode object/array values (verified in `@tanstack/router-core` `searchParams.ts`), so `sort` and `filters` are arrays of objects in `validateSearch`; simple per-column filters are flat string keys (arrays comma-joined); defaults omitted on write.
- `createDataTableSearchSchema({ columnIds, filterableColumnIds?, defaultSort, defaultPerPage, perPageOptions?, maxPerPage = 100 })`; throws at creation on column ids colliding with reserved keys; sort capped at 3 (matches §6.4), duplicate ids keep the first; out-of-range `perPage` falls back to default; `sort: []` means unsorted.
- `isFilterValid` is stricter than tablecn: `isBetween` needs exactly two non-blank ends.
- No barrel: `shared/lib` imports modules directly.

## T2 decision record

- `useDataTable({ data, columns, pageCount, getRowId?, search, searchConfig, onSearchChange, initialState?, enableAdvancedFilter?, enableRowSelection?, debounceMs? })` is router-agnostic: the feature passes the validated `search` and `onSearchChange = (next, { replace }) => navigate({ search: next, replace })`. `next` is the full table search with defaults omitted; non-table route keys must be merged by the caller.
- Text/number/range filters debounced; select/date/multiSelect and reset immediate; sort keeps page, filter/perPage reset page to 1.
- `DataTable` props: `{ table, total, children (toolbar), actionBar?, isPending?, errorMessage?, onRetry?, empty, isFetching?, isPlaceholderData?, pageSizeOptions?, skeletonRows? }`; toolbar stays visible in empty/error/out-of-range states (reset must remain reachable); skeleton only on first load. `aria-sort` set on the `th`.
- v9 facts: no `table.getState()` (use `table.state`), `ColumnVisibilityState`, `columnOrderingFeature` needed for first/last column, core row model used under manual modes, `metaHelper<DataTableColumnMeta>()`.
- Date filters store local-midnight timestamps (browser timezone).

## T3 decision record

- Keyboard drag: dnd-kit `KeyboardSensor` calls `preventDefault` on the activating keydown, so the guard now ignores only non-`keydown` events with `defaultPrevented`.
- `useDataTable` returns `advanced: { filters, joinOperator, debounceMs, setFilters, setJoinOperator, reset }`; incomplete rows never reach the URL; filter/join changes reset page to 1; default sort is `initialState.sorting`. `useFilterDraft` holds builder rows locally; `filterId` is `filter-N` from `nextFilterId`.
- `isRelativeToToday` hidden in builders. Filter menu chips cannot change their field (remove and re-add). Trigger-level Backspace removal of the last filter not ported; row-level Delete/Backspace and Ctrl/Cmd+Shift+F/S kept.
- In-memory `data-table-fake-server.ts` evaluates advanced filters, joins and multi-sort for stories/tests.

## T4 decision record

- Page-size constants, `clampLimit`, `toLimitOffset` live in `@base-template/db/lib/pagination` (lowest package; auth and api already depend on db). Auth no longer exports them.
- Canonical vocabulary (variants, operators, join operators, `OPERATORS_BY_VARIANT`, `MAX_SORT_ITEMS`, `SERVER_OPERATORS`) in pure `packages/db/src/lib/list-vocabulary.ts`; web reaches it via `@base-template/api/lib/list-vocabulary` (re-export, no new web dependency); web keeps labelled operator lists with a test asserting parity.
- `createListInput({ sortableColumns, filterableColumns: { id: variant }, defaultSort? })` (packages/api/src/lib/list-input.ts): allowlisted ids, declared variant must match, operator valid per variant, `isRelativeToToday` rejected, strict filter objects, value shapes checked; strings ≤256, lists ≤100.
- `buildListQuery({ columns, input, tieBreakers? })` → `{ where, orderBy, limit, offset }`, `countListRows(db, table, where)` (packages/db/src/lib/list-query.ts). `isEmpty` per variant (`col::text = ''` for text/select; tablecn's `col = ''` errors on non-text columns).
- Drizzle rc.4: `new PgDialect().sqlToQuery(sql)` for SQL assertions; `and()`/`or()` unwrap single items.

## T5 decision record

- URL shape: `validateSearch` = `createDataTableSearchSchema` (+ drop filters the server list input would reject) per route; `stripSearchParams(defaults)` keeps the default view out of the URL. `/settings/activity` sorts by `createdAt|action|targetType`, filters by `createdAt|action|actor|targetType`; `/admin/activity` adds `scope`, `organization`. Search state is advanced mode: `sort` and `filters` are JSON arrays, plus `page`, `perPage`, `joinOperator`. `mergeTableSearch` replaces only the table's keys, so other route search keys survive.
- Server input: `toListInput(createListInput(config), search)` drops filters the server would reject and clamps `page` to `getMaxPage(perPage)`; allowlists come from the shared `audit-list-config`, pinned to the search config by a test.
- Export: read-only CSV of the selected rows of the current page (`toCsv`: RFC 4180 quoting, CRLF, formula-guard `'` prefix for text starting with `=+-@` tab CR, ISO dates, UTF-8 BOM added by the button). Selection resets when the query (page, sort, filters) changes. No new procedures or permissions.
- Actor filter: member picker on the org log, free-text id on the platform log; platform organization filter is a free-text id.
- Timezone (T4 note confirmed): the `base-template-postgres` container reports `TimeZone = Etc/UTC`, and drizzle's `timestamp` (mode date, no tz) serializes `Date` as a UTC ISO string, so the day windows (`[ts, ts+24h)`, local-midnight epoch from the browser) compare as absolute instants regardless of the session timezone; only `defaultNow()` depends on the session zone (UTC here). Production DB must keep a UTC session timezone. 24h windows still ignore DST.

## T6 decision record

- better-auth 1.7.5 admin `list-users` (verified in `node_modules/better-auth/dist/plugins/admin/routes.mjs` and the drizzle adapter, plus the docs): paging (`limit`/`offset`), ONE sort (`sortBy` + `sortDirection`), at most ONE text search (`searchField` email|name, `searchOperator` contains|starts_with|ends_with) AND at most ONE other filter (`filterField`/`filterOperator`/`filterValue`), AND-ed; `total` is the filtered count. No `or`, no multi-sort, no second facet. Gotchas: the search is a case-sensitive `LIKE` with unescaped `%`/`_`, the endpoint swallows query errors into `{ users: [], total: 0 }`, and `role` is a comma-separated string (multi-role users).
- Approach (users): the shared `createListInput` over `platformUsersListConfig` (sort `email|name|role|createdAt`; filters `email`/`name` text, `role`/`status` select); `toPlatformUsersQuery` maps it onto the supported subset and throws `BAD_REQUEST` for anything beyond (several sorts, two searches, two facets, `or` with several filters, operators other than `iLike`/`eq`). Email search is lowercased (better-auth stores lowercase) and wildcards are escaped via the shared `escapeLikePattern`. `role` maps to a `contains` filter (so `user,superadmin` matches `superadmin`), `status` to `banned eq true|false`. The existing `platform.users.list` guards (`user:list`) are unchanged.
- Approach (organizations): not better-auth. The list was already a Drizzle query; it now uses `buildListQuery` + `countListRows` (exact total, `hasMore` removed, tie-break by id) over `platformOrganizationsListConfig` (sort `name|slug|createdAt`; filters `name`, `slug` text). Spec §4.4/§7 lumped it with the better-auth lists; the code never used better-auth for it. Guard `organization:list` unchanged.
- Search shapes (simple mode, `stripSearchParams` defaults, thin routes): users `?email=|name=` (one), `?role=|status=` (one), `sort` (one item), `page`, `perPage`; organizations `?name=&slug=`, `sort` (up to 3), `page`, `perPage`. `validateSearch` drops values the server would reject, keeps one key per exclusive group and one sort item for users, and resets `filters`/`joinOperator`. The page keeps the latest choice when the user sets a second key in a group (`limitExclusiveFilters`, previous search compared).
- New shared helpers (`shared/lib/data-table/simple-filters.ts`): `simpleSearchToFilters`, `limitExclusiveFilters`, `normalizeSimpleSearch`. Admin lists have no selection column and no action bar (spec §2: no mutating bulk actions).
- T5 follow-ups: (f) the exact `count(*)` stays, with the rationale and the cap/estimate options written next to `queryAuditLog` (retention bounds the table, the tenant condition narrows most requests); no cap added. (g) `ORG_AUDIT_ACTIONS` is `ORG_LOG_ACTIONS`, `queryAuditLog`'s `scope` parameter is `tenantCondition`, column-id ownership comments say the list contract defines the ids.
